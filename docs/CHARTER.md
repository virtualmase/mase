# MASE Charter

**Name:** MASE — **Mergers + Acquisitions Software Engineer** in its original domain context, extended here as a front-end systems practice for the virtualmase portfolio.  
**Property owner:** Mason Nguyen / virtualmase.  
**Repository role:** The canonical source for MASE front-end research, evaluation criteria, prototypes, quality checks, and release records.  
**Initial status:** Private foundation. No client data, deal data, user telemetry, or autonomous agent operations are in scope.

## Reader and user promise

MASE serves founders, product leaders, operators, and engineering teams who need an AI-era interface to do more than resemble a model-generated demo. The user promise is straightforward: **MASE helps turn AI capability into interfaces people can understand, challenge, and use responsibly.**

The first public audience is technically literate leaders who can recognize the gap between a visually plausible prototype and a trustworthy product experience. MASE should offer them a compact explanation, a repeatable method, and working proofs—not a generic catalog of design trends.

## Strategic posture

| MASE does | MASE does not |
|---|---|
| Makes user tasks, system state, sources, control points, and fallback paths clearer. | Claim universal superiority over Claude, Codex, Gemini, any vendor, or any human practitioner. |
| Uses models as accelerators inside an evidence-led product process. | Treat the first generated interface as a finished product. |
| Benchmarks specific flows against explicit criteria. | Publish “wins” without scope, test method, limitations, and reproducibility notes. |
| Prototypes locally and releases in reversible increments. | Collect sensitive information, files, or analytics data by default. |
| Makes accessibility, performance, semantics, and user control part of quality. | Add decorative AI effects, opaque automation, or manipulative conversion mechanics. |

## Quality thesis

> **A MASE interface is ahead of the curve when it remains useful after the visual fashion changes, the model changes, the user changes device, or the workflow encounters uncertainty.**

The quality system therefore prioritizes the following.

| Dimension | Test question |
|---|---|
| **Task clarity** | Can a first-time user identify the primary job and next meaningful action without a tutorial? |
| **State legibility** | Can the user tell what the system knows, is doing, has changed, and cannot do? |
| **Human authority** | Are consequential decisions, overrides, review points, and escalation paths visible where needed? |
| **Accessibility** | Can the essential task be completed by keyboard and understood with semantic structure and clear focus? |
| **Responsiveness** | Does each critical interaction provide timely feedback without unnecessary scripts or animation? |
| **Privacy and data restraint** | Does the prototype avoid collection by default and clearly state any data boundary? |
| **Evidence** | Is the claim matched to research, a test, or an explicitly bounded observation? |
| **Reversibility** | Can the change be inspected, rolled back, or retired without compromising another property? |

## Decision rights

| Decision | Accountable role | Required record |
|---|---|---|
| Public claims, offer language, or comparative statements | Property owner | Dated decision note with evidence and scope. |
| New user-data collection, account, agent, upload, CRM, or analytics integration | Property owner plus relevant security/privacy reviewer | Data boundary, retention, vendor, permission, and rollback record. |
| Prototype implementation and maintenance changes | Maintainer | Pull request or descriptive commit, test result, and rollback point. |
| Public release or domain assignment | Property owner | Release note with route, deployment target, and acceptance result. |
| Deprecation, deletion, or archival | Property owner | Retention and redirect decision, with provenance preserved. |

## Relationships to other properties

MASE may link to the virtualmase MASE page as a current public entry surface. It remains an independent source repository and must not silently become the canonical repository for Coreweaver Labs, ARM, Arctura, or another property. Shared methods may be reused only when source rights, purpose, and attribution are clear.

## First-year success signals

The useful early signals are qualitative and bounded: credible practitioners can accurately restate the MASE method; a first proof surfaces a real design question; a reviewer can verify the accessibility and no-data boundary; and repeated work reveals a component, pattern, or benchmark worth maintaining. Traffic volume, social engagement, or model-comparison bravado are not sufficient evidence of product value.
